# 常见问题

## 安装 / 更新

### 启动时提示模组缺失或「文件哈希不匹配」

packwiz 更新失败通常是这三种原因：

1. **作者的仓库还没推送**：运行 `build-updater.ps1` 之后必须先 `commit` + `push`，再同步 Gitee，否则玩家拿到的还是旧哈希。
2. **Gitee raw 链接缓存**：Gitee 同步后有几十分钟内的缓存延迟，等几分钟重试即可。
3. **实例里有你手动放进去、又没提交进仓库的模组**：packwiz 只同步仓库里有的文件，额外的模组会造成校验差异。建议保持实例干净，自己加的模组单独记录。

### 打了更新补丁之后内存 / Java 参数变了

正常现象。`ChaosWorld-AutoUpdate-Patch.zip` 会覆盖实例配置文件，把内存和 Java 参数重置为默认值，覆盖后到启动器里再调一次。

### HMCL / PCL2 能不能自动更新

不能。自动更新依赖启动器的预启动命令（Prism / MultiMC），其他启动器请直接使用作者发布的整合包安装包，更新时重新导入。

## 游戏内

### JEI 里查不到某个配方

大概率是**被整合包删掉了**。作者用 `kubejs/server_scripts/删除并隐藏配方.js` 批量删除并在 JEI 中隐藏了一批配方，随后用新配方替换。请以 JEI 当前显示的结果为准；确实什么都没有的物品，看任务书的对应章节。

### 暮色森林传送门做不出来 / 丢进去没反应

整合包清空了原版的传送门激活矿词，改为只认 **`chaosworld_core:twilight_catalyst`（暮色催化剂）**。用错物品是打不开的。

### 任务奖励为什么没自动发给我

任务书配置里 `default_autoclaim_rewards = "disabled"`，**奖励需要手动点击领取**。任务书右上角可以一次性领取当前章节的所有奖励。

### 任务线某一章是灰的

任务书使用**线性推进（linear）**模式，需要先完成前置章节。另外有些章节是奖励章（「生物全收集」「材料金字塔」），不强制推进主线。

### 时钟右键没反应 / 硬币兑换不了

- 潜行（按住 Shift）状态下**不会触发**兑换，这是刻意设计的，方便你正常使用物品。
- 手持时钟右键：兑换**背包里所有**硬币；手持硬币右键：只兑换手上这一格；手持时钟 **Shift 右键容器**：兑换容器里的硬币。
- 兑换成功会有音效、粒子和余额提示。余额单位显示为 `C`。

### 打凋零掉了一大堆锭

这是自定义掉落（`凋零锭掉落.js`）：额外按权重抽取 `50 + 抢夺等级 × 20` 次金属锭，不带抢夺平均 50 个左右，属于设计内容。

### 有办法白拿开局物资吗

聊天栏发送 **`新手大礼包`**（每个存档一次）。发第二次会被施加漂浮效果——这是作者彩蛋，不是 bug。

### 暮色森林怎么没有阶段限制

作者写了 `stages.js` 做阶段门槛，但**整份脚本目前是注释状态**，所以没有限制。将来启用后，没有 `twilight_forest` 阶段进入暮色森林会被传送回主世界。

## 性能

### 卡顿 / 掉帧

按这个顺序排查：

1. 关闭光影（内置 Complementary Reimagined + Euphoria Patches，对显卡要求不低）。
2. 降低模拟距离与渲染距离。
3. 检查是否有大量 `jdttimeaccelerators` 时间加速器在同时运行（它会让周围机器一起加速）。
4. 确认优化模组没有被手动禁用：Sodium / Sodium Extra / ModernFix / FerriteCore / ImmediatelyFast / EntityCulling / lithium / Clumps。
5. 内存不足会表现为频繁卡顿：给 6–12 GB，不要给到系统和显卡抢内存。

### 中文显示不全 / 部分模组是英文

整合包自带汉化资源包 `Minecraft-Mod-Language-Modpack-Converted-1.21.1.zip`，确认它在资源包列表里已启用。另外 `jecharacters` 提供了拼音搜索，搜索时可以直接输入拼音。

## 多人游戏

- 整合包内置 FTB Teams / FTB Chunks / FTB Essentials，`/home`、`/tpa`、`/back` 这类指令的权限在服务器端配置里控制。
- 任务书是**每个玩家独立进度**还是团队共享，取决于 FTB Teams 的组队设置。
- 服务器部署同样建议用 packwiz 的 `pack.toml` 做同步源，保证客户端与服务端模组完全一致。

## 还有别的问题？

- 先看整合包目录下的 `logs/latest.log` 与 `crash-reports/`，报错信息里的模组名基本能定位问题。
